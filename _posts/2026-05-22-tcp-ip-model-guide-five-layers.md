안녕하세요! 오늘은 인터넷과 모든 현대 네트워크 통신의 근간이 되는 **TCP/IP 프로토콜 스택(Internet Protocol Suite)**에 대해 알아보겠습니다. IP, TCP, UDP, HTTP와 같은 용어들을 들어보셨을 겁니다. 이들은 모두 TCP/IP라는 거대한 프로토콜 가족의 일원입니다.

이 글에서는 복잡한 네트워크 동작 과정을 계층별로 나누어 정리한 **TCP/IP 모델**을 중심으로, 데이터가 어떻게 전달되는지 그 원리를 살펴보겠습니다.

## 1. 프로토콜과 표준의 중요성

**프로토콜(Protocol)**은 네트워크 상에서 장치들이 통신하기 위해 지켜야 하는 '약속' 또는 '규칙'입니다. 컴퓨터가 사용하는 언어라고 생각하면 쉽습니다.

과거에는 IBM이나 Apple 같은 제조사들이 자신들만의 고유(Proprietary) 프로토콜을 사용했기 때문에, 서로 다른 제조사의 기기끼리는 대화가 불가능했습니다. 하지만 오늘날에는 **표준(Standard)** 덕분에 기기 종류에 상관없이 전 세계 어디서든 통신이 가능합니다.

### 주요 표준 기구
- **IEEE (Institute of Electrical and Electronics Engineers):** LAN 기술(Ethernet - 802.3, Wi-Fi - 802.11)과 같은 물리적, 하위 계층 표준을 정의합니다.
- **IETF (Internet Engineering Task Force):** TCP, IP, HTTP, DNS 등 인터넷에서 사용되는 대부분의 상위 프로토콜을 정의하며, 이를 **RFC(Request for Comments)**라는 문서로 공개합니다.

## 2. TCP/IP 모델의 5계층 구조

네트워크는 매우 복잡한 일을 수행하지만, 이를 계층(Layer)으로 나누면 이해하기 훨씬 쉽습니다. 여기서는 실무와 학습에서 가장 널리 쓰이는 **5계층 모델**을 기준으로 설명합니다.

### 5층: 애플리케이션 계층 (Application Layer)
- **역할:** 사용자 인터페이스를 제공하고 데이터의 형식을 정의합니다.
- **주요 프로토콜:** HTTP(웹), FTP(파일 전송), SMTP(이메일) 등.
- **특징:** 네트워크 장비(라우터 등)는 이 계층의 내용을 신경 쓰지 않습니다. 오직 통신하는 두 호스트(PC, 서버)만 이 데이터를 해석합니다.

### 4층: 전송 계층 (Transport Layer)
- **역할:** 애플리케이션 프로세스 간의 **엔드 투 엔드(End-to-End)** 통신을 담당합니다.
- **식별자:** **포트 번호(Port Number)**를 사용해 데이터를 어떤 프로그램(웹 서버인지, 파일 서버인지)에 전달할지 결정합니다.
- **주요 프로토콜:** TCP, UDP.

### 3층: 인터넷 계층 (Internet Layer)
- **역할:** 서로 다른 네트워크 간에 데이터를 전달(라우팅)합니다.
- **식별자:** **IP 주소**를 사용합니다.
- **주요 장비:** 라우터(Router).

### 2층: 로컬 네트워크 계층 (Local Network / Data Link Layer)
- **역할:** 동일한 로컬 네트워크(LAN) 내에서 장치 간의 데이터 전달(**Hop-to-Hop**)을 담당합니다.
- **식별자:** **MAC 주소**를 사용합니다.
- **주요 장비:** 스위치(Switch).

### 1층: 물리 계층 (Physical Layer)
- **역할:** 데이터를 전기적, 광학적, 또는 무선 신호로 변환하여 실제 매체(케이블, 공기 등)를 통해 전송합니다.
- **주요 요소:** 이더넷 케이블, 광섬유, NIC(랜카드) 등.

## 3. 데이터 캡슐화와 역캡슐화

데이터가 네트워크를 통해 전달될 때는 각 계층을 지나면서 필요한 정보가 덧붙여지거나 제거됩니다.

### 캡슐화 (Encapsulation)
송신 호스트에서 데이터가 하위 계층으로 내려가면서 각 계층의 정보를 담은 **헤더(Header)**를 붙이는 과정입니다.
1. **Data** (애플리케이션)
2. **L4 Header + Data** = **세그먼트(Segment)** 또는 **데이터그램(Datagram)**
3. **L3 Header + L4 PDU** = **패킷(Packet)**
4. **L2 Header + L3 PDU + L2 Trailer** = **프레임(Frame)**

### 역캡슐화 (Decapsulation)
수신 호스트에서 데이터를 받으면 상위 계층으로 올리면서 헤더를 하나씩 제거하고 최종적으로 원래의 데이터만 남기는 과정입니다.

---

## 4. PDU (Protocol Data Unit) 요약

각 계층에서 취급하는 데이터 단위(PDU)의 이름은 다음과 같습니다. 이 용어들은 네트워크 엔지니어 간의 대화에서 매우 중요합니다.

| 계층 | PDU 이름 | 주요 주소/식별자 |
| :--- | :--- | :--- |
| **Layer 4** | 세그먼트(TCP) / 데이터그램(UDP) | 포트 번호 |
| **Layer 3** | 패킷(Packet) | IP 주소 |
| **Layer 2** | 프레임(Frame) | MAC 주소 |
| **Layer 1** | 비트(Bits) | - |

## 5. TCP/IP vs OSI 모델

네트워크를 공부하다 보면 **OSI 7계층 모델**도 접하게 됩니다. 

- **OSI 모델:** 이론적이고 교육적인 목적으로 주로 사용됩니다 (물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 계층).
- **TCP/IP 모델:** 실무에서 실제로 사용되는 프로토콜 스택입니다.

실무에서는 TCP/IP의 상위 3계층(세션, 표현, 응용)을 하나로 묶어 '애플리케이션 계층'으로 부르는 경우가 많으며, 이를 OSI 모델의 번호를 빌려와 **Layer 7**이라고 부르기도 합니다.

## 마치며

TCP/IP 모델은 네트워크의 지도와 같습니다. 우리가 학습하는 이더넷, IP 주소지정, 라우팅, TCP 연결 등 모든 기술은 이 모델의 특정 계층에 위치합니다. 이 계층 구조를 머릿속에 잘 그려둔다면, 앞으로 배울 복잡한 네트워크 개념들도 제 자리를 찾아 이해하기 훨씬 쉬워질 것입니다.
