안녕하세요! 오늘은 인터넷과 모든 네트워크 통신의 근간이 되는 **인터넷 프로토콜 스위트(Internet Protocol Suite)**, 즉 **TCP/IP 모델**에 대해 알아보겠습니다. 

IP, TCP, UDP, HTTP와 같은 용어들을 들어보셨을 겁니다. 이들은 모두 TCP/IP라는 거대한 프로토콜 가족의 일원입니다. 이 글에서는 복잡한 네트워크 동작 과정을 계층별로 나누어 살펴보고, 데이터가 어떻게 전달되는지 그 큰 그림을 그려보겠습니다.

## 1. 프로토콜과 표준화의 중요성

**프로토콜(Protocol)**이란 네트워크상에서 장치들이 통신하기 위해 지켜야 하는 규칙의 집합입니다. 쉽게 말해 컴퓨터들이 대화하는 '언어'와 같습니다.

과거에는 IBM이나 Apple 같은 제조사들이 자신들만의 독자적인 프로토콜을 사용했습니다. 이 때문에 서로 다른 제조사의 장비끼리는 통신이 불가능한 문제가 있었습니다. 이를 해결하기 위해 등장한 것이 **벤더 중립적인 표준 프로토콜**입니다.

### 주요 표준 기구
*   **IEEE (Institute of Electrical and Electronics Engineers):** 이더넷(802.3), Wi-Fi(802.11) 등 물리적인 사양과 로컬 네트워크 표준을 정의합니다.
*   **IETF (Internet Engineering Task Force):** TCP, IP, UDP, HTTP, DNS 등 인터넷 운영에 필요한 핵심 프로토콜을 정의하며, 이를 **RFC(Request for Comments)**라는 문서로 공개합니다.

## 2. TCP/IP 모델의 5계층 구조

네트워크의 복잡한 기능을 이해하기 쉽게 나누는 방법 중 가장 실용적인 모델이 바로 **5계층 모델**입니다. 각 계층은 하위 계층의 서비스를 이용하고 상위 계층에 서비스를 제공합니다.

### 우편 시스템 비유
네트워크 계층을 이해하는 가장 좋은 방법은 편지를 보내는 과정에 비유하는 것입니다.

1.  **내용 (Application):** 편지에 적힌 실제 메시지.
2.  **수신인 (Transport):** 집 안의 누구(Bob)에게 전달될지 지정 (포트 번호).
3.  **주소 (Internet):** 어느 집(10.1.1.1)으로 갈지 지정 (IP 주소).
4.  **현지 배달 (Local Network):** 우체국 간 이동, 트럭이나 비행기 이용 (MAC 주소).
5.  **도로/인프라 (Physical):** 실제 트럭이 달리는 길 (케이블, 무선 신호).

## 3. 계층별 상세 역할

### 1계층: 물리 계층 (Physical Layer)
비트(0과 1)를 전기, 광학 또는 무선 신호로 변환하여 실제 매체를 통해 전송합니다.
*   **주요 요소:** 케이블(UTP, 광섬유), NIC(네트워크 카드), 커넥터 등.

### 2계층: 로컬 네트워크 계층 (Local Network / Data Link Layer)
로컬 네트워크 내에서 **홉-바이-홉(Hop-to-Hop)** 전달을 담당합니다.
*   **식별자:** MAC 주소
*   **장비:** 스위치(Switch)
*   **프로토콜:** 이더넷(Ethernet), Wi-Fi

### 3계층: 인터넷 계층 (Internet / Network Layer)
서로 다른 네트워크 간의 **엔드-투-엔드(End-to-End)** 통신을 담당합니다. 소스 호스트에서 목적지 호스트까지 최적의 경로를 찾습니다.
*   **식별자:** IP 주소
*   **장비:** 라우터(Router)
*   **프로토콜:** IPv4, IPv6, ICMP

### 4계층: 전송 계층 (Transport Layer)
호스트 내의 특정 애플리케이션 프로세스 간 통신을 담당합니다.
*   **식별자:** 포트 번호 (예: HTTP는 80, FTP는 21)
*   **프로토콜:** TCP(신뢰성 중시), UDP(속도 중시)

### 5계층: 애플리케이션 계층 (Application Layer)
사용자가 직접 사용하는 소프트웨어와 네트워크가 만나는 지점입니다. 데이터의 형식을 정의합니다.
*   **프로토콜:** HTTP(웹), FTP(파일 전송), SMTP(이메일) 등.
*   *참고: OSI 모델에서는 이를 7계층이라고 부르기도 합니다.*

## 4. 캡슐화(Encapsulation)와 역캡슐화(Decapsulation)

데이터가 네트워크를 통해 전송될 때, 각 계층을 지나며 필요한 정보(헤더)가 덧붙여지거나 제거됩니다.

1.  **캡슐화 (송신 측):**
    *   애플리케이션 데이터 생성.
    *   **L4 헤더 추가:** 데이터 + L4 Header = **세그먼트(Segment)** 또는 **데이터그램(Datagram)**.
    *   **L3 헤더 추가:** 세그먼트 + L3 Header = **패킷(Packet)**.
    *   **L2 헤더/트레일러 추가:** 패킷 + L2 Header/Trailer = **프레임(Frame)**.
    *   **L1 전송:** 프레임을 비트 단위 신호로 변환하여 전송.

2.  **역캡슐화 (수신 측):**
    *   수신 장치는 신호를 받아 프레임을 복원하고, 계층을 올라가며 헤더를 하나씩 제거(확인)하여 최종적으로 원본 데이터를 애플리케이션에 전달합니다.

## 5. OSI 7계층 모델과의 비교

학계나 교재에서는 **OSI 7계층 모델**을 자주 언급합니다. 하지만 실제 산업 현장에서는 TCP/IP 모델이 표준으로 자리 잡았습니다.

| 계층 번호 | OSI 7계층 모델 | 5계층 TCP/IP 모델 | PDU 명칭 |
| :--- | :--- | :--- | :--- |
| **Layer 7** | Application | **Application** | Data |
| **Layer 6** | Presentation | (Application 통합) | Data |
| **Layer 5** | Session | (Application 통합) | Data |
| **Layer 4** | **Transport** | **Transport** | Segment / Datagram |
| **Layer 3** | **Network** | **Internet (Network)** | Packet |
| **Layer 2** | **Data Link** | **Local Network (Data Link)** | Frame |
| **Layer 1** | **Physical** | **Physical** | Bits |

## 결론

TCP/IP 모델은 복잡한 네트워크 통신을 이해하는 아주 유용한 지도입니다. 각 계층이 독립적으로 분리되어 있기 때문에, 예를 들어 유선 이더넷에서 Wi-Fi로 통신 방식이 바뀌어도 웹 브라우저(애플리케이션 계층)는 아무런 수정 없이 그대로 작동할 수 있는 유연성을 가집니다.

앞으로 네트워크를 공부하면서 마주하게 될 이더넷 스위칭, IP 라우팅, TCP 핸드셰이킹 등의 주제들을 이 5계층 모델의 어디에 해당하는지 끼워 맞춰 보세요. 전체적인 구조가 훨씬 명확하게 보일 것입니다.
