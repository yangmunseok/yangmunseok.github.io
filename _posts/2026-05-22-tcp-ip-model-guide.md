인터넷과 현대의 모든 네트워크 통신을 가능하게 하는 핵심, 바로 **TCP/IP 프로토콜 스위트(Protocol Suite)**입니다. 우리가 흔히 사용하는 IP, TCP, UDP, HTTP 등이 모두 이 가족에 속하죠.

이번 포스트에서는 복잡한 네트워크 통신 과정을 계층별로 나누어 정리한 **TCP/IP 모델**을 단계별로 살펴보겠습니다. 네트워크 엔지니어나 개발자라면 반드시 알아야 할 기본 개념들을 정리했습니다.

---

## 1. 프로토콜과 표준의 중요성

**프로토콜(Protocol)**이란 네트워크를 통해 장치 간에 데이터를 주고받는 규칙의 집합입니다. 쉽게 말해 컴퓨터들이 소통하는 '언어'와 같습니다.

과거에는 특정 벤더(IBM 등) 전용 프로토콜을 사용했기 때문에 서로 다른 제조사의 장치끼리 통신하기가 매우 어려웠습니다. 이를 해결하기 위해 오늘날에는 **벤더 중립적인 표준(Standards)**을 사용합니다.

- **IEEE (전기전자공학자협회):** LAN 기술(Ethernet - 802.3, Wi-Fi - 802.11) 표준 정의. 물리적인 사양과 메세지 포맷을 다룹니다.
- **IETF (인터넷 국제 표준 기구):** TCP, IP, UDP, HTTP, DNS 등 인터넷 핵심 프로토콜 정의. 이러한 표준은 **RFC(Requests for Comments)**라는 문서로 공개됩니다.

---

## 2. TCP/IP 5계층 모델 구성

네트워크는 데이터를 이동시키기 위해 신호 전송, 로컬 전달, 라우팅, 연결 유지 등 수많은 일을 수행합니다. 이를 효율적으로 관리하기 위해 기능별로 나눈 것이 '계층 모델'입니다. 여기서는 실무적으로 가장 많이 쓰이는 **5계층 모델**을 기준으로 설명합니다.

### Layer 5: 애플리케이션 계층 (Application Layer)
- **역할:** 사용자가 사용하는 소프트웨어와 네트워크 서비스 간의 인터페이스 제공. 데이터 생성 및 해석.
- **주요 프로토콜:** HTTP(웹), FTP(파일 전송), SMTP(이메일), DNS 등.
- **특징:** 통신하는 호스트(PC, 서버)에서만 데이터를 해석하며, 중간 장비(라우터 등)는 이 계층의 내용을 신경 쓰지 않습니다.

### Layer 4: 전송 계층 (Transport Layer)
- **역할:** 애플리케이션 프로세스 간의 **엔드 투 엔드(End-to-End)** 통신 지원.
- **핵심 개념:** **포트 번호(Port Number)**를 사용하여 어떤 서비스(웹: 80, FTP: 21 등)에 데이터를 전달할지 식별합니다.
- **주요 프로토콜:** TCP, UDP.

### Layer 3: 인터넷 계층 (Internet Layer)
- **역할:** 서로 다른 네트워크 간에 데이터를 전달(라우팅).
- **핵심 개념:** **IP 주소**를 사용하며, **라우터**가 이 계층에서 작동합니다.
- **주요 프로토콜:** IPv4, IPv6, ICMP.

### Layer 2: 로컬 네트워크 계층 (Local Network / Data Link Layer)
- **역할:** 동일한 로컬 네트워크(LAN) 내에서의 데이터 전달.
- **핵심 개념:** **MAC 주소**를 사용하며, **스위치**가 이 계층에서 작동합니다. 홉 투 홉(Hop-to-Hop) 전달을 담당합니다.
- **주요 프로토콜:** Ethernet, Wi-Fi.

### Layer 1: 물리 계층 (Physical Layer)
- **역할:** 데이터를 비트(0과 1) 단위로 변환하여 물리적 매체로 전송.
- **구성 요소:** 케이블(UTP, 광케이블), 커넥터, NIC(네트워크 인터페이스 카드), 신호 방식(전기적, 광학적, 무선 신호).

## 3. 캡슐화와 역캡슐화 (Encapsulation & Decapsulation)

데이터가 네트워크를 통해 전달될 때, 각 계층을 지나면서 필요한 정보가 추가되거나 제거됩니다.

1. **캡슐화 (Encapsulation):** 송신 측에서 상위 계층의 데이터에 하위 계층의 헤더(Header)를 붙여나가는 과정입니다.
   - L4 헤더(포트 정보) 추가 → L3 헤더(IP 주소) 추가 → L2 헤더/트레일러(MAC 주소 및 오류 검사) 추가.
2. **역캡슐화 (Decapsulation):** 수신 측에서 하위 계층부터 헤더를 확인하고 제거하며 상위 계층으로 데이터를 올리는 과정입니다.

### PDU (Protocol Data Unit): 각 단계에서의 데이터 이름
- **세그먼트(Segment) / 데이터그램(Datagram):** L4에서 헤더가 붙은 상태 (TCP는 세그먼트, UDP는 데이터그램).
- **패킷(Packet):** L3에서 IP 헤더가 붙은 상태.
- **프레임(Frame):** L2에서 헤더와 트레일러가 붙은 상태. (실제로 선로 위를 흐르는 단위)

---

## 4. 계층 간의 상호작용

- **인접 계층 상호작용 (Adjacent-layer Interaction):** 한 장치 내에서 상위 계층이 하위 계층의 서비스를 이용하는 것. (예: L3는 L2에게 패킷 전달을 요청)
- **동일 계층 상호작용 (Same-layer Interaction):** 서로 다른 장치의 동일한 계층끼리 논리적으로 소통하는 것. (예: 송신측 L4 포트 번호는 수신측 L4에서 해석됨)

---

## 5. OSI 7계층 모델과의 비교

학계에서는 ISO에서 정의한 **OSI 7계층 모델**을 표준 참조 모델로 자주 언급합니다.

| 계층 (Layer) | OSI 모델 | TCP/IP (5계층) |
| :--- | :--- | :--- |
| Layer 7 | **Application** | **Application** |
| Layer 6 | **Presentation** | (Application에 포함) |
| Layer 5 | **Session** | (Application에 포함) |
| Layer 4 | **Transport** | **Transport** |
| Layer 3 | **Network** | **Internet (Network)** |
| Layer 2 | **Data Link** | **Local Network (Data Link)** |
| Layer 1 | **Physical** | **Physical** |

현대 네트워크는 대부분 TCP/IP 스택을 기반으로 작동하지만, 용어는 OSI 모델의 계층 번호(L2, L3 등)를 빌려서 사용하는 경우가 많습니다.

## 요약 및 결론

TCP/IP 모델은 네트워크 통신의 복잡성을 줄여주는 훌륭한 도구입니다. 각 계층은 독립적인 역할을 수행하므로, 하드웨어(물리 계층)가 바뀌어도 소프트웨어(애플리케이션 계층)를 수정할 필요가 없는 **모듈화**의 장점을 가집니다.

- **L1/L2:** 근거리 통신 (Ethernet, MAC)
- **L3:** 원거리 경로 최적화 (IP, Router)
- **L4:** 서비스 구분 및 신뢰성 (TCP/UDP, Port)
- **L5:** 실제 서비스 데이터 (HTTP, Data)

이 프레임워크를 머릿속에 그려두면, 앞으로 배울 IP 어드레싱, 라우팅, 스위칭 등의 기술들이 네트워크 전체 구조 중 어디에 위치하는지 쉽게 이해할 수 있습니다.
